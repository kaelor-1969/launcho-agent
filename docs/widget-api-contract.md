# قراردادهای اتصال ویجت

## محدودهٔ مشتری

دریافت شماره موبایل و تمام مراحل پرداخت از دستیار و demo حذف شده‌اند. ورودی تلفن، روش پرداخت، محاسبه مبلغ، اقساط، لینک درگاه و وضعیت تراکنش جزو قرارداد نیستند. دورهٔ اشتراک صرفاً یک انتخاب اطلاعاتی است و تعهد مالی ایجاد نمی‌کند.

مسیر نهایی فقط نام کسب‌وکار ← دسته‌بندی ← دوره اشتراک ← قالب ← مرور اطلاعات ← تأیید ← لینک پیش‌نویس است. سؤال و بررسی دامنه حذف شده‌اند. تا آماده‌شدن بک‌اند، مسیر ساخت فقط نمایشی است و این موضوع در صفحه و ویجت اعلام می‌شود.

## API موجود

این ویجت از حالت قدیمی `POST /api/chat` استفاده می‌کند: ورودی `{ "message": "..." }` و خروجی `{ "reply": "..." }`، بدون sessionId و امکان ساخت. متن پیام و پاسخ با `textContent` نمایش داده می‌شود.

کامیت جدید ریموت `dbe6246` هستهٔ session با مسیرهای ایجاد جلسه، گفتگو، ویرایش، مرور و تأیید اضافه کرده است؛ مرجع آن [قرارداد هسته](core-api-contract.md) است. این مسیرها با adapter تک-endpoint زیر یکسان نیستند. ویجت به آن‌ها متصل نشده و factory ساخت واقعی هسته هم فعلاً `can_create=False` است. دادهٔ احراز هویت session، نام‌های فیلد و پاسخ‌ها برای اتصال آینده نیازمند تطبیق صریح‌اند؛ هیچ endpoint حدس زده نمی‌شود.

## adapter پیشنهادی مراحل

این API هنوز پیاده نشده است؛ `data-workflow-url` فقط پس از تحویل و تأیید بک‌اند واقعی تنظیم شود. نصب واقعی fallback به mock ندارد. endpoint ساخت‌یافته باید POST/JSON، HTTPS، CORS برای origin ویجت و session سمت سرور داشته باشد. کلید سرور به مرورگر ارسال نمی‌شود. transport از `credentials: omit` استفاده می‌کند؛ `sessionId` باید تصادفی، کوتاه‌عمر، غیرقابل حدس و محدود به همان جلسه باشد. احراز هویت حساب کاربری قرارداد مستقلی لازم دارد و credential نباید در URL باشد.

نمونهٔ درخواست:

```json
{"action":"next","sessionId":"opaque-session","revision":3,"data":{"field":"subscription","value":"6"}}
```

برای شروع، `sessionId` و `revision` برابر null هستند. پاسخ یک view کامل است:

```json
{
  "sessionId":"opaque-session", "revision":4,
  "kind":"field", "field":"subscription",
  "title":"دوره اشتراک را مشخص کن", "value":"6",
  "options":[{"id":"6","label":"شش‌ماهه"}],
  "actions":[{"id":"next","label":"ادامه"}]
}
```

مقادیر مجاز فعلی `kind`: `field`، `template`، `review` و `draft`.

مقادیر مجاز `field`: `businessName`، `category` و `subscription`. قالب با view مستقل `template` انتخاب می‌شود. `options` و `value` دادهٔ همان فیلد هستند. در هر view یک سؤال یا انتخاب فعال وجود دارد. `title`، `description`، `rows:[{label,value}]` و برچسب اقدامات فقط متن هستند و HTML تفسیر نمی‌شود.

| action | ورودی اضافه | مسئولیت |
| --- | --- | --- |
| start | بدون داده | ایجاد یا بازیابی جلسه و مرحلهٔ اول |
| next | field، value | اعتبارسنجی و ثبت مقدار و view بعدی |
| selectTemplate | template:{id,name,image} | بررسی قالب و برگرداندن مرحلهٔ بعد |
| browseTemplates | بدون داده | رویداد انتخاب قالب در میزبان؛ بدون درخواست API |
| edit | بدون داده | نمایش انتخاب فیلد قابل ویرایش |
| edit:نام‌فیلد | بدون داده | فقط فیلدهای مجاز یا template؛ بازگشت به مرور بعد از ویرایش |
| createDraft | idempotencyKey در ریشه | فقط از مرور با تأیید صریح؛ پاسخ draft با draftId، confirmed:true و draftUrl معتبر |

شناسهٔ اقدام‌های قابل نمایش محدود به همین مجموعه است؛ اقدام‌های قدیمی و ناشناخته رد می‌شوند. `start` و `selectTemplate` از منطق رابط فراخوانی می‌شوند. `createDraft` قفل همزمانی دارد و retry دستی همان `idempotencyKey` را می‌فرستد. پس از ویرایش و مرور تازه، کلید تازه ساخته می‌شود. سرور آینده باید نتیجهٔ همان کلید را حتی پس از timeout بازیابی کند؛ بک‌اند فعلی این تضمین را ندارد، بنابراین ساخت واقعی فعال نیست. retry خودکار وجود ندارد.

## مرور و پیش‌نویس

مرور فقط نام، دسته‌بندی، دوره اشتراک و قالب را به همین ترتیب نشان می‌دهد؛ شماره موبایل، دامنه یا مبلغی ندارد. دوره‌های demo سه‌ماهه، شش‌ماهه و سالانه‌اند و هیچ قیمت یا تخفیفی در آن‌ها وعده داده نمی‌شود. هر چهار مورد قابل ویرایش‌اند و بعد از ویرایش مستقیماً به مرور بازمی‌گردند. ویرایش قالب با همان hook میزبان انجام می‌شود.

نمونهٔ پاسخ نهایی فعلی:

```json
{"sessionId":"opaque-session","revision":7,"kind":"draft","title":"پیش‌نویس نمایشی آماده شد.","draftId":"demo-only","confirmed":true,"draftUrl":"http://127.0.0.1:8000/widget/draft-preview.html","description":"نمونهٔ ثابت؛ فروشگاه واقعی ساخته نشده است.","actions":[]}
```

`draftUrl` فقط در view نوع `draft` پس از تأیید پذیرفته می‌شود. URL باید مطلق HTTP/HTTPS و بدون نام کاربری یا رمز باشد؛ javascript، data و URL نسبی رد می‌شوند. HTTP برای اجرای محلی است و استقرار واقعی باید HTTPS داشته باشد. لینک با اقدام کاربر در تب جدید با `noopener noreferrer` باز می‌شود.

در demo، URL نسبت به ماژول به `draft-preview.html` محلی ساخته می‌شود؛ پورت یا دامنه‌ای ثابت نشده است. این صفحه یک نمونهٔ ثابت قالب الماس است و روشن اعلام می‌کند به اطلاعات واردشده متصل نیست. هیچ داده‌ای در URL، storage یا backend ذخیره نمی‌شود. تأیید به معنای ایجاد فروشگاه، حساب یا تعهد مالی نیست.

پاسخ‌های قدیمی با فیلدهای `mobile`، `setupPayment` یا `domain`، نوع‌های `payment` یا `result`، داده‌های `domainStatus`، `quote`، `checkoutUrl`، `transactionId`، `paymentStatus` یا `verified` و اقدام‌های خارج از فهرست رد می‌شوند و به فرم یا لینک تبدیل نمی‌شوند.

## خطا

پیشنهاد کدهای سرور آینده: 422 مقدار نامعتبر، 409 revision قدیمی، 410 جلسهٔ منقضی، 429 محدودیت و 5xx اختلال. پاسخ ناموفق یا خارج از قرارداد view موفق نمی‌سازد؛ رابط view قبلی را حفظ و خطا و retry دستی نشان می‌دهد. پاسخ باید متعلق به همان session باشد و revision عقب نرود. خطای اختصاصی فیلد و بازیابی جلسهٔ منقضی قرارداد تکمیلی لازم دارند.

هستهٔ جدید برای خطاهای gateway پاسخ HTTP غیرموفق برمی‌گرداند؛ ویجت فعلی آن‌ها را با پیام عمومی و retry دستی مدیریت می‌کند. نمایش کد خطای اختصاصی و بازیابی session به اتصال آینده مربوط است.

## سایت میزبان و قالب

demo از یک fixture قالب الماس استفاده می‌کند؛ شناسهٔ عمومی `almas` جای تأیید شناسهٔ داخلی API را نمی‌گیرد. کاتالوگ جدیدی ساخته نشده است.

```javascript
window.addEventListener('launcho:templates:open', event => {
  event.detail.select({id: realTemplate.id, name: realTemplate.name, image: realTemplate.image});
});
// جایگزین callback:
window.LaunchoWidget.selectTemplate({id, name, image});
```

میزبان باید hook را نصب کند؛ loader دربارهٔ DOM سایت فرض نمی‌کند. انتخاب قالب فقط از iframe ثبت‌شده با origin، source و channel معتبر پذیرفته می‌شود؛ سرور آینده باید شناسهٔ قالب را دوباره بررسی کند. دادهٔ ناقص و پروتکل نامعتبر رد می‌شود.

حفظ داده فقط تا زنده‌بودن iframe در همان صفحه است. navigation و refresh داده را پاک می‌کنند. حفظ جلسه بین صفحات به API بازیابی و توکن امن نیاز دارد. رابط هیچ داده‌ای در localStorage یا sessionStorage ذخیره نمی‌کند و شماره موبایل درخواست نمی‌کند.

# قرارداد داخلی پیشنهاد مالی — هماهنگی با هسته

نسخه: `internal-offers-v1`، تاریخ ۲۰۲۶-۱۱-۱۳. این سند، امضاها و قواعد پیشنهادی قبلی همین فایل را جایگزین می‌کند. قرارداد رسمی لانچو دریافت نشده؛ هیچ سیاست تجاری واقعی از این سند استنباط نشود.

شاخهٔ تهیه: `work/launcho-mock-catalog`. کامیت مبنای تغییرات محلی: `d72d9dcf05239ef63cf1e203d8dcb72b6e4478a7`. این شناسه کامیت مبنای توسعه است، نه کامیت نهایی این تحویل. مسیر سند در شاخهٔ تحویل `docs/financial-offers-stage5.md` است؛ بعد از push از همان شاخه دریافت شود. بستهٔ patch قبلی فقط snapshot پیش از انتشار است.

## مرحله و امضای دقیق آداپتور

```python
# LocalMockGateway
match_price_offers(kind, plan_months=None, *, message=None, history=None, step=None, offer_state=None)

# LaunchoDraftGateway
match_checkout_offers(kind, plan_months, *, message=None, history=None,
                      step=None, offer_state=None)
```

پیام فعلی پوشانده‌شده در message است و در history تکرار نمی‌شود. history فقط پیام‌های قبلی پوشانده‌شدهٔ همان جلسه است. آداپتور متن/تاریخچه را به HTTP نمی‌فرستد؛ فقط برچسب‌های استنتاج‌شدهٔ مالی را ارسال می‌کند.

step دقیقاً یکی از نام‌های زیر است و باید توسط بک‌اند تعیین شود:

| نام | معنا |
| --- | --- |
| guidance | راهنمایی |
| collecting_preferences | جمع‌آوری انتخاب‌ها |
| review_ready | انتخاب‌های لازم کامل‌اند ولی مرور معتبر فعال نداریم |
| awaiting_confirmation | مرور معتبر و جاری، منتظر تأیید |
| draft_created | پیش‌نویس با نتیجهٔ موفق معتبر ساخته شده |

اولویت تشخیص پیشنهادی برای پارسا: نتیجهٔ ساخت معتبر، سپس مرور معتبر، سپس کامل‌بودن انتخاب‌ها، سپس جمع‌آوری، سپس راهنمایی. شکست/نتیجهٔ نامعلوم ساخت، draft_created نیست. مرور منقضی یا ناسازگار با revision، awaiting_confirmation نیست. محاسبهٔ وضعیت و lifecycle در مالکیت پارساست.

شمارش فیلدها، عدد ۴ و actual_step استفاده نمی‌شوند. در HTTP داخلی mock، مرحلهٔ عددی با 422 رد می‌شود. آداپتور ورودی قدیمی/نامعتبر را به مرحلهٔ فرضی تبدیل نمی‌کند و بدون ارسال درخواست offers=[] می‌دهد. نبود متن، step معتبر یا offer_state صریح نیز درخواست پیشنهاد ایجاد نمی‌کند.

## وضعیت پایدار؛ مسئول هسته

```json
{
  "shownOfferIds": [],
  "rejectedOfferIds": [],
  "anyFinancialOfferShown": false,
  "financialOffersDeclined": false
}
```

این شیء offer_state است؛ فقط هسته بعد از احراز مالکیت جلسه آن را از SQLite می‌خواند. null یا نبود شیء به معنی جلسهٔ تازه نیست؛ آداپتور پیشنهاد نمی‌گیرد. {} فقط وقتی مجاز است که هسته نبود سابقهٔ نمایش/رد در همان جلسه را احراز کرده باشد. مقدار رشته‌ای به‌جای boolean، شناسهٔ خراب، تکراری یا فیلد اضافه رد می‌شود.

تا تصمیم محصول، رفتار محافظه‌کارانهٔ موجود حفظ می‌شود: پس از نمایش هر پیشنهاد مالی، پیشنهاد خودکار تازه در همان جلسه نمایش داده نشود. anyFinancialOfferShown یا حتی shownOfferIds غیرخالی هر پیشنهاد بعدی را متوقف می‌کند. financialOffersDeclined هم همه را متوقف می‌کند. rejectedOfferIds فقط شناسه‌های ردشده را فیلتر می‌کند. رفع این محدودیت برای پیشنهاد متفاوت، یا پس از درخواست دوبارهٔ کاربر، تصمیم تجاری باز است؛ از حدس فعال نشده است.

پارسا: ثبت shownOfferIds و anyFinancialOfferShown باید همراه ذخیرهٔ پاسخ، پس از اعتبارسنجی نهایی و در همان تراکنش انجام شود؛ دریافت نتیجه از آداپتور به معنی نمایش نیست. رد پیشنهاد نیز باید مستقل از ۱۲ پیام اخیر ذخیره شود. retry، هم‌زمانی و restart در مالکیت هسته تست شوند. آداپتور state را ذخیره یا mutate نمی‌کند.

## تشخیص نیاز و رد پیشنهاد

اعتراض قیمت یا بودجه از پیام جاری استخراج می‌شود. سؤال قیمت یا تخفیف به‌تنهایی اعتراض نیست. low_upfront فقط با اشارهٔ صریح به اقساط/پرداخت اولیه یا دشواری پرداخت یکجا استنتاج می‌شود؛ گرانی به‌تنهایی این نیاز را ثابت نمی‌کند. رد پیشنهاد در تاریخچه هم لحاظ می‌شود؛ state پایدار بر تاریخچه اولویت محافظه‌کارانه دارد.

قواعد مبتنی بر الگو هستند و فهم کامل نفی، کنایه یا زبان ادعا نمی‌شود.

## خروجی ساختاریافته

هر تابع پس از اعتبارسنجی `{"offers": [...]}` می‌دهد. نمونهٔ صرفاً آزمایشی:

```json
{
  "offerId": "demo_campaign",
  "type": "discount",
  "kind": "shop",
  "displayText": "این جشنواره صرفاً آزمایشی است و برای خرید اعتبار ندارد؛ هیچ تخفیفی اعمال نمی‌شود.",
  "expiresAt": "2099-01-01T00:00:00Z",
  "source": {
    "type": "internal_fixture",
    "reference": "content/launcho-mock.json",
    "approvalEvidence": null
  },
  "simulation": true,
  "eligibleStages": ["review_ready"],
  "planMonths": [3, 6, 12]
}
```

تاریخ دور این نمونه یک ثابت مصنوعی برای تکرارپذیری fixture است؛ مدت اعتبار سرویس واقعی نیست. mock فقط shop در review_ready با price و low_upfront و discountAlreadyShown=false را واجد پیشنهاد آزمایشی می‌کند؛ این صلاحیت تجاری واقعی نیست. website و سایر مرحله‌ها نمونهٔ پیشنهاد ندارند، اما مراحل معتبرند و 200 با فهرست خالی می‌گیرند.

قواعد:

- offerId پایدار، ۱ تا ۱۰۰ کاراکتر از حروف انگلیسی، رقم، underscore و خط تیره؛ شناسهٔ تکراری در یک پاسخ رد است.
- type فقط payment_option یا discount؛ kind فقط shop/website.
- displayText غیرخالی، حداکثر ۱۶۰ کاراکتر، بدون اطلاعات حساس قابل تشخیص، لینک، markup یا newline.
- expiresAt اجباری با timezone؛ عدد timestamp، تاریخ بدون timezone، مقدار نامعتبر یا منقضی قابل نمایش نیست. در لحظهٔ برابر انقضا نیز منقضی است.
- eligibleStages و planMonths اجباری و بدون تکرار؛ نبود محدودیت‌ها به معنی مجوز همگانی نیست.
- simulation=true فقط با internal_fixture و فقط در حالت local_mock پذیرفته می‌شود؛ در live حذف می‌شود.
- simulation=false نیازمند source.type=official_api، مرجع HTTPS روی میزبان دقیق launcho.ir بدون credential/query/fragment و approvalEvidence غیرخالی است. اگر میزبان رسمی متفاوت بود، فقط با سند معتبر mapper را اصلاح می‌کنیم.
- approvalEvidence رشتهٔ مدرک است، نه اثبات خودکار صحت آن؛ دریافت پاسخ از transport معتبر و تأیید مدرک توسط مالک محصول همچنان لازم است. مقادیر رسمی‌نمای تست، مدرک واقعی نیستند.
- پاسخ بدساخت/شناسهٔ تکراری به GatewayUnavailable تبدیل می‌شود؛ پاسخ ساختاری معتبر ولی منقضی/ناسازگار/دیده‌شده فیلتر می‌شود و می‌تواند offers=[] شود. قطعی شبکه فهرست خالی موفق معرفی نمی‌شود.

این شکل، قرارداد داخلی canonical است؛ آداپتور واقعی بدون دریافت قرارداد رسمی و mapper معتبر «آزموده‌شده» محسوب نمی‌شود.

## مرز نمایش

آداپتور خروجی canonical معتبر می‌دهد؛ نمایش آن در هسته هنوز به تغییر پارسا وابسته است. checkoutOffer رشته‌ای همچنان نمایش داده نمی‌شود. پارسا نباید با تبدیل displayText به رشته، metadata را حذف و فیلتر فعلی را دور بزند. پذیرش خروجی ساختاریافته در مسیر پاسخ باید پس از توافق مرز نمایش به‌صورت مشترک متصل شود؛ در این تحویل ساخت/نمایش واقعی فعال نشده است.

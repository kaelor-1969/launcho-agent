# گزارش مرحلهٔ ۶: مسیر نهایی نمایشی

تاریخ: ۲۰۲۶-۱۱-۰۸

مسیر نهایی دقیقاً این است:

نام کسب‌وکار ← دسته‌بندی ← دوره اشتراک ← قالب ← مرور اطلاعات ← تأیید ← لینک پیش‌نویس نمایشی.

سؤال دامنه، وضعیت و بررسی آن از fixture، renderer و قرارداد حذف شدند. دوره اشتراک پیش از قالب انتخاب می‌شود؛ هر چهار انتخاب قابل ویرایش‌اند و پس از ویرایش به مرور بازمی‌گردند. شماره موبایل و پرداخت نیز همچنان خارج از محدوده‌اند.

## لینک پایانی

فقط بعد از تأیید، لینک `draft-preview.html` نمایش داده می‌شود. URL نسبت به محل ماژول ساخته می‌شود و پورت ثابت یا دادهٔ کاربر در آن نیست. صفحه در تب تازه با `noopener noreferrer` باز می‌شود و صریحاً اعلام می‌کند نمونه‌ای ثابت است، به اطلاعات واردشده متصل نیست و فروشگاه واقعی ایجاد نشده است. برچسب نمایشی در demo، ویجت و مقصد لینک وجود دارد.

schema برای `draft` علاوه بر `draftId` و `confirmed:true`، `draftUrl` مطلق HTTP/HTTPS و بدون credential می‌خواهد؛ javascript، data، URL نسبی، لینک پیش از تأیید و پاسخ تأییدنشده رد می‌شوند.

در سه مسیر demo، درخواست API واقعی، درخواست بیرونی یا خطای JavaScript ثبت نشد و localStorage و sessionStorage خالی ماندند. تصاویر مرور دسکتاپ، لینک موبایل و صفحهٔ مقصد در عرض ۳۲۰ بازبینی شدند.

## بازتولید

```powershell
# ترمینال اول، بدون نیاز به بک‌اند:
python tests/widget_preview_server.py
# ترمینال دوم، نیازمند Playwright و Chrome:
python tests/widget_workflow_browser.py
```

خروجی داده و تصاویر در `artifacts/widget-stage6/` است. نمونه‌های انتخابی برای تحویل در پوشهٔ `docs/widget-evidence/` ثبت می‌شوند.

## محدودیت‌ها

- لینک، پیش‌نویس شخصی‌سازی‌شده یا فروشگاه واقعی نیست؛ نمونهٔ ثابت است.
- بک‌اند جدید هستهٔ گفتگو در ریموت موجود است، اما قرارداد session آن با adapter تک-endpoint این رابط متفاوت است. هیچ اتصال خودکار به آن انجام نشده و مسیر ساخت همچنان demo است.
- گوشی واقعی، صفحه‌کلید واقعی و Safari بررسی نشده‌اند.

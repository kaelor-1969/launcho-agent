# گزارش مرحلهٔ ۲: تعامل با ویجت

تاریخ: ۲۰۲۶-۱۱-۰۸، مبنا: کامیت `5c67380`

## نتیجه

صفحهٔ `/widget/demo.html` در Chrome با سه اندازهٔ ۱۲۸۰×۹۰۰، ۳۹۰×۸۴۴ و ۳۲۰×۵۶۸ بررسی شد. هر سه سناریوی تعاملی پاس شدند. دو سناریوی مستقل نیز مسیر واقعی `sendMessage` را با API شبیه‌سازی‌شده در اندازهٔ دسکتاپ و موبایل بررسی کردند و پاس شدند.

در هر سناریوی demo چهار پیام کاربر و چهار پاسخ ثبت شد و هیچ درخواست API یا خطای JavaScript رخ نداد. در هر سناریوی API، پس از ارسال اولیه ۲۰ بار Enter، submit و کلیک ارسال تحریک شد؛ فقط یک درخواست با متن مورد انتظار ثبت شد. بستن و بازکردن پنل در زمان انتظار نیز درخواست تازه‌ای ایجاد نکرد.

## اصلاح انجام‌شده

پاسخ demo همگام بود؛ نشانگر انتظار حتی تا فریم بعدی مرورگر باقی نمی‌ماند. آزمایش قبل از اصلاح نشان داد انتظار هم بلافاصله پس از submit و هم در فریم بعدی مخفی است، در حالی که پاسخ از قبل اضافه شده است.

در `frontend/widget.js` فقط در حالت صریح demo، تأخیر ۷۰۰ میلی‌ثانیه‌ای اضافه شد تا انتظار و قفل ارسال در نمونه قابل مشاهده باشند. مسیر ارسال به API از این تأخیر استفاده نمی‌کند. هیچ درخواست واقعی AI ارسال نشد.

## بازتولید و خروجی‌ها

سرور frontend باید در دسترس باشد؛ سپس:

```powershell
python tests/widget_interactions_browser.py --base-url http://127.0.0.1:8000
```

این اسکریپت به Playwright و Chrome نصب‌شده نیاز دارد. برای اجرای فقط دو سناریوی API، گزینهٔ `--transport-only` را اضافه کنید. API با route مرورگر جایگزین می‌شود؛ ویژگی `data-demo` فقط در همان context آزمایشی غیرفعال می‌شود تا مسیر transport بررسی شود. فایل اصلی demo تغییر نمی‌کند.

خروجی محلی در `artifacts/widget-stage2/` است: ۹ تصویر در حالت‌های انتظار، مرور پیام‌های قدیمی و گفتگو، به همراه `report.json` برای سه سناریوی demo و `transport-report.json` برای اجرای مستقل دو سناریوی API. پوشهٔ artifacts در گیت نادیده گرفته می‌شود و تصاویر باید هنگام تحویل PR ضمیمه شوند.

## بررسی دستی

۱. `/widget/demo.html` را باز کنید و دکمهٔ گفتگو را بزنید.
۲. یک جملهٔ فارسی دارای نیم‌فاصله بنویسید؛ Shift+Enter را برای خط جدید امتحان کنید.
۳. پیام را بفرستید؛ در زمان «در حال نوشتن…» یک متن دیگر بنویسید و چند بار Enter بزنید. فقط پیام اول باید ارسال شود و متن دوم باقی بماند.
۴. پنل را ببندید و دوباره باز کنید؛ پیام‌ها و پیش‌نویس باید حفظ شوند.
۵. با چند پیام بلند، گفتگو را طولانی و پیام‌های قبلی را مرور کنید.

## محدودیت‌ها و باقی‌مانده‌ها

- سرور بررسی فقط فایل‌های frontend را با نگاشت `/widget/` ارائه می‌کند؛ اجرای FastAPI در این محیط هنوز به علت دریافت‌نشدن وابستگی‌ها بررسی نشده است.
- موبایل و IME شبیه‌سازی شده‌اند؛ دستگاه واقعی، صفحه‌کلید واقعی فارسی و Safari بررسی نشده‌اند.
- شبیه‌سازی اولیهٔ پیمایش با پنج حرکت برای رسیدن به ابتدای محتوای بلند کافی نبود؛ آزمون به پیمایش تا رسیدن به ابتدای محتوا با سقف ۳۰ حرکت اصلاح شد. تغییری در کد پیمایش ویجت لازم نبود.
- سناریوهای خطای سرور، قطع شبکه، پاسخ نامعتبر، بررسی امنیت پاسخ و اصلاح مسیر ساخت فروشگاه مربوط به مراحل بعد هستند.

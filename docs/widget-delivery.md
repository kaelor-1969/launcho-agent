# تحویل ویجت

آخرین اصلاح ظاهری: رنگ نهایی دکمه از `static/design.html` به loader منتقل و پیشنهادهای شروع از بخش پیمایش پیام‌ها خارج شدند. نتیجه اجرای مجدد ۱۵ تست unit/static و ۸ سناریوی مرورگر و محدوده بررسی در [گزارش تطبیق ظاهری](widget-visual-review.md) ثبت شده است.

## تصمیم ظاهری نهایی

در ادامه کار، کاربر خواست «ظاهر کامیت قبلی» برگردد. مبنا کامیت موجود ویجت `04a8489` است؛ کامیت قبل از آن اصلاً ویجت ندارد. استایل چت، هدر LAUNCHO، خوش‌آمد قبلی، قاب گرادیانی متحرک، اندازه متن و ابعاد ۳۸۰×۴۵۰ / دکمه ۵۸ به همان نسخه برگشتند. تنها CSS مراحل جدید به انتهای استایل قبلی اضافه شده است. رنگ‌ها، چیدمان جدید هدر، جهت جدید حباب‌ها و اندازه‌های ۳۸۰×۶۴۰ پیشنهادی اولیه دیگر خروجی نهایی نیستند؛ دستور بعدی کاربر اولویت دارد. جایگزینی منطق اسکرول مراحل باعث می‌شود قاب متحرک یا هدر هنگام جابه‌جایی مراحل از دید خارج نشود.

## چه چیزهایی آماده بود؟

loader بدون build با Shadow DOM، نصب غیرتکراری، iframe تنبل، handshake امن، تم روشن/تیره، فونت محلی، حفظ حافظه با بستن، Escape و focus، ارسال امن پیام، composition و retry دستی از قبل موجود بود. این بخش‌ها با آزمون واقعی Chrome، دو origin، دسکتاپ و موبایل بررسی شدند. API واقعی chat و backend و prompt دست‌نخورده‌اند.

## چه چیزهایی تکمیل شد؟

- offset دسکتاپ/موبایل قابل تنظیم و نام دسترس‌پذیر دکمه.
- renderer داده‌محور مراحل با یک ورودی/انتخاب در هر مرحله، بدون موتور تصمیم‌گیری production.
- مدل نمایشی نام، دسته، دامنه، قالب، موبایل، اشتراک و روش پرداخت؛ ارقام فارسی/عربی تلفن به انگلیسی تبدیل می‌شوند.
- وضعیت‌های دامنه، قفل درخواست و بی‌اعتبارشدن نتیجه با تغییر نام دامنه.
- hook میزبان برای دیدن و انتخاب قالب، برگشت شناسه/نام/تصویر و تغییر قالب؛ بدون کاتالوگ جدید.
- مرور و انتخاب فیلد برای ویرایش، برگشت به مرور اصلاح‌شده و تأیید صریح پیش‌نویس.
- قفل کلیک همزمان، idempotencyKey ثابت برای retry دستی ایجاد، بدون retry خودکار.
- کارت پیش‌نویس، ادامه به پرداخت، انتخاب اشتراک و روش پرداخت، quote با واحد صریح و نمایش تفکیک هزینه/اقساط؛ تاریخ سررسید حدس زده نمی‌شود.
- نمایش نتیجه موفقِ تأییدشده، ناموفق/لغوشده و نامشخص؛ استعلام پیش از اقدام بعدی در حالت نامشخص.
- timeout و اعتبارسنجی ساختار پاسخ؛ پاسخ نامعتبر یا موفقیت پرداخت بدون verified رد می‌شود.
- demo با برچسب روشن؛ هیچ درخواست AI، ثبت دامنه، ایجاد واقعی یا پرداخت واقعی ندارد. دکمه پرداخت واقعی در demo غیرفعال است و کنترل‌های نتیجه صرفاً fixture آزمایشی‌اند.

## چه چیزی به API واقعی وصل است؟

فقط chat. API موجود پیام را به سرویس AI می‌فرستد، اما در تست‌ها با mock جایگزین شده است؛ صحت حساب AI یا پاسخ مدل واقعی در این کار بررسی نشده است. بعضی خطاهای AI در API فعلی HTTP 200 و reply متنی هستند؛ رابط نمی‌تواند آن‌ها را از پاسخ عادی تفکیک کند.

تمام مسیر ساخت در demo از `workflow-demo.js` می‌آید. در production فقط `workflow-api.js` آدرس تحویل‌داده‌شده را مصرف می‌کند و بدون آن، «ساخت فروشگاه» همان سؤال به chat موجود است. هیچ endpoint ساخت یا پرداخت در backend ساخته نشده و هیچ موفقیت واقعی اختراع نشده است.

## فایل‌ها و قراردادها

شرح نقش تک‌تک فایل‌های جدید/تغییریافته در جدول README است. جزئیات ورودی/خروجی/خطا/session و مسئولیت نفر اول، hook سایت میزبان و دارایی‌های نفر سوم در [widget-api-contract.md](widget-api-contract.md) است. وضعیت اولیه در [widget-gap-review.md](widget-gap-review.md) ثبت شده است.

نفر اول باید API مراحل و بازیابی session، شناسه داخلی قالب و اعتبارسنجی انتخاب، دامنه، quote با واحد/انقضا/سررسیدها، ایجاد idempotent و استعلام تراکنش را تحویل دهد. تیم سایت باید hook انتخاب قالب را به بخش موجود متصل کند. نفر سوم باید لوگو/آواتار نهایی و تصاویر canonical قالب‌ها را تأیید کند؛ فونت فعلی آماده است. thumbnail الماس از تصویر عمومی همان قالب در سایت گرفته شده و فقط در demo استفاده می‌شود.

## اجرا و بررسی

دستورهای کامل نصب و اجرا در README است. با تنظیمات محیطی موجود:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Demo: http://127.0.0.1:8000/widget/demo.html

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
$env:LAUNCHO_BROWSER_CHANNEL='chrome'
.\.venv\Scripts\python.exe tests/widget_browser.py
```

۱۳ تست unit/static و ۸ سناریوی نهایی مرورگر پاس شده‌اند: چهار ترکیب تم/viewport چت با نصب cross-origin، سه عرض مراحل (۱۲۸۰، ۳۹۰ و ۳۲۰) و adapter واقعی با پاسخ شبیه‌سازی‌شده. شش مبلغ ترکیبی اشتراک/روش پرداخت با ارقام مشخصات تطبیق داده شدند. خطای ایجاد با retry دستی همان کلید idempotency را حفظ کرد؛ پاسخ موفقیت پرداخت بدون تأیید رد شد. آزمون مرورگر نتایج را در `artifacts/widget/report.json` نوشته است. تصاویر `flow-{1280,390,320}-{start,collection,template,review,cost,error}.png`، viewport کوتاه، خطای پیش‌نویس و تصاویر چت دو تم در همان پوشه قرار دارند. تصاویر شروع، مرور، هزینه و viewport کوتاه واقعاً باز و بررسی شدند. سناریوهای نمایشی هیچ درخواست بیرونی یا خطای JavaScript/console ندارند و localStorage خالی می‌ماند. فایل‌ها/تصاویر خروجی در git نادیده گرفته می‌شوند.

آزمون سرویس دامنه، فروشگاه یا تراکنش واقعی، نصب روی production سایت، احراز هویت و بازیابی session بین صفحات، مرورگر Safari و کیبورد فیزیکی گوشی انجام نشده‌اند. اطلاعات شخصی در حافظه همان iframe هستند و با refresh پاک می‌شوند. در مرحله پیاده‌سازی و بررسی، پیش از دستور بعدی کاربر برای commit و push، هیچ commit، push، PR یا انتشاری انجام نشد.

## ادغام هنگام push

پس از دستور کاربر برای commit و push، ریموت چهار کامیت تازه داشت. تاریخچه‌ها بدون force push ادغام شدند. تنظیمات Render، فایل ارائه، مسیر `/static`، مدل‌های ChatRequest/ChatResponse و مدیریت خطای سرور از ریموت حفظ شدند؛ `/widget` نیز باقی ماند. trim و محدودیت طول موجود به ChatRequest متمرکز منتقل شد. آزمون سلامت با پاسخ توسعه‌یافته ریموت هماهنگ شد و دو آزمون برای حفظ مسیر static و جلوگیری از افشای خطای داخلی اضافه شدند؛ هر ۱۵ تست unit/static پاس شدند. هیچ تغییری در سرویس AI یا prompt انجام نشد.

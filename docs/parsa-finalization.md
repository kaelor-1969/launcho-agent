# تحویل هستهٔ پیشنهاد و عملیات پارسا

مبنای این تغییر main با شناسهٔ b086116 است. قرارداد پیشنهاد در financial-offers-stage5.md مبنای پیاده‌سازی قرار گرفت.

## رفتار هسته

- ستون offer_state با migration افزایشی به sessions اضافه می‌شود. سابقهٔ shown_local_offers و نشانه‌های نمایش/رد در history قدیمی حفظ می‌شوند.
- shownOfferIds، rejectedOfferIds، anyFinancialOfferShown و financialOffersDeclined مستقل از تاریخچهٔ محدود ذخیره می‌شوند. رد صریح پیشنهاد در پیام کاربر، محدودیت کل عمر جلسه را حفظ می‌کند.
- مرحله از ترجیحات، review جاری، revision، انقضا و نتیجهٔ موفق ساخت تعیین می‌شود. creating/unknown مرحلهٔ draft_created نمی‌گیرند.
- پیام جاری پوشانده‌شده، history قبلی همان جلسه، مرحله و state واقعی به توابع تطبیق ارسال می‌شوند.
- خروجی با validated_offers دوباره اعتبارسنجی می‌شود. متن مجاز و metadata کامل در financialOffer پاسخ /api/chat قرار می‌گیرند. متن displayText به reply افزوده می‌شود تا رابط فعلی آن را نمایش دهد. فرانت جدید باید برای کارت از metadata استفاده کند و همان متن را دوباره به حباب اضافه نکند.
- پیشنهاد به context مدل وارد نمی‌شود. نمایش متن و ثبت state بر عهدهٔ هسته است. انقضا و مرحله پس از تأخیر شبکه در تراکنش نهایی دوباره بررسی می‌شوند.
- state، history و پاسخ requestId در همان تراکنش ذخیره می‌شوند. دریافت پاسخ آداپتور به‌تنهایی state را تغییر نمی‌دهد.
- جدول chat_responses پاسخ کامل و hash پیام پوشانده‌شده را برای هر session/requestId نگه می‌دارد. retry همان درخواست، پس از عبور از ۱۲ پیام و restart نیز پاسخ ذخیره‌شده را می‌گیرد. بدنهٔ متفاوت با همان شناسه 409 می‌گیرد. رکوردها با انقضای جلسه پاک می‌شوند.
- مفهوم shown در این قرارداد، ثبت اتمیک پیشنهاد در پاسخ تحویلی سرور است. تأیید دریافت یا مشاهدهٔ بصری مرورگر قرارداد مستقلی لازم دارد.

## فعال‌سازی

در local_mock پیشنهادهای simulation معتبر قابل نمایش‌اند. برای live، مقدار LAUNCHO_ENABLE_FINANCIAL_OFFERS=1 پس از تأیید منبع رسمی و شرایط تجاری لازم است. پیش‌فرض خاموش است. حتی با فعال‌سازی، پیشنهاد simulation در live پذیرفته نمی‌شود. approvalEvidence در schema جای بررسی واقعی صاحب محصول را نمی‌گیرد.

متغیر فوق در env.example مستند شده است. به‌علت بازبودن تأیید منبع تجاری، روی سرویس عمومی فعال نشود.

## اعتبارسنجی

تست‌های tests/test_core_financial_offers.py مسیر HTTP، متن حساس، مالکیت جلسه، metadata، انقضا، مرحلهٔ review، رد پیشنهاد، history rolloff، restart، retry، هم‌زمانی، rollback تراکنش و backup/restore را پوشش می‌دهند. آزمون کنترل‌شدهٔ live از دادهٔ مصنوعی استفاده می‌کند.

فرمان‌های بررسی از ریشهٔ مخزن اجرا شوند.

```powershell
$env:PYTHONUTF8='1'
python -m unittest discover -s tests -v
python tests/check_demo.py --backend-only --check-core --agent-port 8050 --mock-port 8051
node --experimental-vm-modules --test tests/widget_session_test.cjs
```

PYTHONUTF8 در CI نیز برای فرایندهای فرزند تنظیم شده است.

اجرای محلی این تحویل با ۱۷۸ تست پایتون موفق شد. آزمون HTTP واقعی محلی برای shop و website شامل مالکیت، revision، تأیید صریح، concurrent replay، preview و status موفق بود. تست JavaScript session نیز موفق شد.

## بررسی Runflare در ۱۴ نوامبر ۲۰۲۶

سرویس 88574 در پروژهٔ 37668 بررسی شد. دیسکی متصل نیست و کران‌جابی وجود ندارد. فرم افزودن دیسک حداقل ۵۱۲ مگابایت را نشان می‌دهد و قیمت همان افزودنی را نمایش نمی‌دهد. موجودی مشاهده‌شده ۲۵٬۵۴۷ تومان بود. liveness از نوع HttpGet روی پورت ۸۰۰۰ و /health/live با period و initial delay برابر ۳۰ ثانیه موجود است.

برای تکمیل عملیات، قیمت دیسک و تأیید هزینه، مقصد بکاپ بیرونی و کانال هشدار لازم‌اند. تعویض کلید قبلی نیز باید توسط صاحب کلید تأیید شود. این موارد در بررسی حاضر انجام‌شده محسوب نمی‌شوند.

پس از اتصال دیسک، مسیر DB فعلی و دادهٔ موجود بررسی و بکاپ گرفته شود. مسیر زیر نمونهٔ پیشنهادی برای دیسک اختصاصی است و باید با محل mount واقعی یکسان شود.

```text
LAUNCHO_ENV=production
LAUNCHO_SESSION_DB=/data/sessions.sqlite3
LAUNCHO_FRAME_ANCESTORS=https://launchox.ir
```

دامنهٔ نهایی launcho.ir پس از هماهنگی نصب به فهرست مجاز افزوده شود. SQLite با یک نمونهٔ سرویس و یک worker اجرا شود. ابزار monitor_backend.py از محیط دارای دسترسی مستقیم به DB و مقصد بکاپ مستقل اجرا شود. بکاپ روی همان دیسک به‌تنهایی نسخهٔ بیرونی نیست.

برای rollback ابتدا بکاپ آنلاین گرفته شود، SHA قبلی استقرار حفظ شود، سپس همان SHA قبلی دوباره مستقر و health و مسیر HTTP بررسی شوند. migration افزایشی است و کد مبنای b086116 ستون و جدول جدید را نادیده می‌گیرد. اگر نسخهٔ قدیمی پیشنهاد نمایش داد، پیش از برگشت به نسخهٔ جدید سابقهٔ آن باید بررسی شود.

# بررسی اطلاعات و API آزمایشی لانچو

اطلاعات سه فایل `content/launcho-public.json`، `content/launcho-mock.json` و `app/mock_launcho.py` در ۱۱ نوامبر ۲۰۲۶ با صفحات رسمی تطبیق داده شد و اصلاحات پس از تأیید کاربر اعمال شدند. این تطبیق، دادهٔ نمونه را به تعرفهٔ زنده یا قرارداد API واقعی تبدیل نمی‌کند. تغییرات محلی‌اند و PR ساخته نشده است.

## قرارداد محلی قیمت پس از تفکیک

`GET /pricing` فیلدهای مشترک، از جمله `setupFees`، `plans` و `domains` را حفظ می‌کند. جزئیات اختصاصی در `serviceDetails.shop` و `serviceDetails.website` هستند. فیلدهای قبلی `setupIncludes`، `planIncludes` و `installment` از ریشهٔ پاسخ بدون نوع خدمت به همین بخش‌ها منتقل شدند.

`GET /pricing?kind=shop` و `GET /pricing?kind=website` فیلدهای مشترک را به همراه `kind` و جزئیات همان نوع در ریشه برمی‌گردانند. نوع نامعتبر رد می‌شود. مصرف‌کنندگان فعلی هسته فیلدهای مشترک را برای اعتبارسنجی می‌خوانند و در حالت محلی برآورد مبلغ ندارند. اعداد همچنان برای تمرین سروری در API باقی می‌مانند و نباید مستقیم در ویجت نمایش داده شوند.

## محدودیت‌های باقی‌مانده

برای پرکردن فهرست گزینه‌های قابل ثبت، قرارداد و دادهٔ مورد تأیید لازم است. مشاهدهٔ نام‌ها و قالب‌ها روی سایت به‌تنهایی قرارداد API نیست؛ در این تغییر، خالی‌بودن فهرست مستند و صریح شده است. درخواست پیشنهاد در `LocalMockGateway.match_price_offers` همچنان شرایط ثابت آزمایشی دارد و بیانگر استنباط نیاز واقعی بازدیدکننده نیست.

ناسازگاری توضیح جلسه در README با کد فعلی ویجت، از بررسی اولیه برای هماهنگی باقی مانده و جزو تغییرات این تطبیق سه فایل نیست. آزمون‌ها بدون تماس واقعی با مدل اجرا می‌شوند و جای ارزیابی همهٔ پاسخ‌های مدل زنده یا اجرای مرورگر واقعی را نمی‌گیرند.

## نتیجهٔ آزمون پس از اصلاحات تأییدشده

`python -m unittest discover -s tests -v`: هر ۷۰ آزمون موفق، شامل ۸ آزمون فایل جدید `test_mock_launcho.py`. این آزمون‌ها علاوه بر عدم نمایش قیمت نمونه، تفکیک پاسخ سایت/فروشگاه، حفظ دادهٔ مشترک در درخواست‌های متوالی، اعلام نبود کاتالوگ معتبر، محدودیت دوره‌های مجاز و تفکیک تخفیف دوره از کمپین را بررسی می‌کنند. `git diff --check` نیز بدون خطا بود.

## اصلاحات

- `content/launcho-mock.json`: عنوان جشنواره «آزمایشی» است؛ متن آن صریحاً اعتبار خرید و اعمال تخفیف را رد می‌کند. دعوت قبلی به بررسی جشنواره در مرحلهٔ پرداخت حذف شد.
- `app/mock_launcho.py`: پاسخ‌های موفق با `simulation: true` و هشدار فارسی برچسب می‌خورند. شکل `ok/data` و داده‌های نمونهٔ `/pricing` برای تمرین قرارداد حفظ شده‌اند.
- `app/services/ai_service.py`: اگر متن پیشنهاد شامل مبلغ، درصد یا ادعای رایگان‌بودن باشد، پیشنهاد نمایش داده نمی‌شود و راهنمای تعرفهٔ رسمی باقی می‌ماند.
- `tests/test_mock_launcho.py`: احراز هویت و برچسب پاسخ‌ها، عبور از API ساختگی به گفتگوی دارای جلسه، عدم نمایش مبالغ در پاسخ و تاریخچه، تکرارنشدن پیشنهاد در نوبت بعد، نبود برآورد قیمت در حالت mock و مسیر قدیمی بدون جلسه بررسی می‌شوند. تماس با مدل و شبکه در این آزمون‌ها جایگزین شده‌اند.

موارد مرجع مفقود و منابع عمومی در جدول زیر با اصلاحات بالا رسیدگی شده‌اند؛ خالی‌بودن گزینه‌ها اکنون صریح است. شرایط ثابت پیشنهاد و ناسازگاری README همچنان محدودیت‌اند.

| فایل | مورد و منبع ناکافی | رفتار فعلی تا زمان تأیید |

## مرز بررسی

`ConversationCore.chat` دادهٔ قیمت و گزینه‌های mock را پیش از فراخوانی مدل خالی می‌کند و `estimate` در حالت محلی مقدار ندارد. اعداد فقط در API آزمایشی دارای احراز هویت باقی می‌مانند. برچسب محیط و متن جشنواره در صفحهٔ میزبان هم آزمایشی‌اند. آزمون‌های این تغییرات اجرای واقعی مرورگر یا ارزیابی پاسخ یک مدل زنده نیستند.

## سابقهٔ آزمون اولیه

- `python -m unittest discover -s tests -v`: هر ۶۶ آزمون موفق، شامل ۴ آزمون جدید این بررسی.
- `node --experimental-vm-modules tests/widget_session_test.cjs`: آزمون‌های جلسه، retry و تأیید دکمه‌ای موفق.
- `git diff --check`: بدون خطا.

وابستگی‌های پایتون پس از مشکل DNS دانلود، از بسته‌های موجود در کش محلی نصب شدند. هیچ درخواست واقعی به مدل ارسال نشد. طبق درخواست صاحب محصول، تغییرات محلی‌اند و ساخت PR تا تأیید او انجام نمی‌شود.

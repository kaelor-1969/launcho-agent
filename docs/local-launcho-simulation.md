# شبیه‌سازی محلی نصب ویجت لانچو

اجرای ویجت اصلی بدون کلید و بدون نیاز به ورودی ترمینال:

```powershell
# Windows، از ریشهٔ مخزن، پس از نصب Python
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe tests/check_demo.py --serve
```

```bash
# macOS، از ریشهٔ مخزن
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python tests/check_demo.py --serve
```

سپس `http://127.0.0.1:8000/widget/widget.html` را باز کنید. اسکریپت حالت محلی را انتخاب می‌کند، تنظیمات مدل و API واقعی را برای فرایندهای فرزند غیرفعال می‌کند و `.env` را تغییر نمی‌دهد. با Ctrl+C هر دو سرویس متوقف می‌شوند. دادهٔ اجرای این اسکریپت موقت است و پس از خروج حذف می‌شود؛ برای نگهداری پیش‌نویس بین اجراها از دو فرمان دستی پایین استفاده کنید. `--keep-open` فقط برای ترمینال تعاملی است؛ در اجرای بدون stdin خطای EOF می‌دهد. `--serve` به stdin وابسته نیست.

در بررسی ۲۰۲۶/۱۱/۱۲، Python موجود در `D:\soft\python\code\launcho-\launcho-agent\venv\Scripts\python.exe` استفاده شد. فرمان‌های macOS از نظر ساختار قابل حمل‌اند، اما روی دستگاه مک اجرا نشده‌اند. نتیجه و محدودیت‌ها در [گزارش تحویل محلی](local-delivery-review.md) ثبت شده‌اند.
قرارداد جاری مسیرها، نمونه‌های درخواست/پاسخ و پیش‌نویس پایدار در [قرارداد محلی mock نسخهٔ ۲](launcho-mock-contract-v2.md) آمده است. ویجت محلی پس از تأیید کاربر از mock پیش‌نویس می‌سازد و آن را در SQLite نگه می‌دارد.

ساختار گزینه‌ها، منابع، وضعیت تأیید و محدودیت سازگاری در [راهنمای کاتالوگ](launcho-catalog.md) است. مسیر قدیمی نیز فهرست مستند خالی را برمی‌گرداند؛ نمونه‌های قدیمی گزینهٔ واقعی ثبت‌نام محسوب نمی‌شوند.

برای بررسی قبل از تحویل، از ریشهٔ مخزن این دستور را اجرا کنید. اسکریپت دو سرویس را روی پورت‌های ۸۰۰۰ و ۸۰۰۱ بالا می‌آورد، فایل‌های ویجت، نمایش پیشنهاد آزمایشی و ارسال مجدد همان پیام را بررسی می‌کند و سرویس‌ها را می‌بندد.

```powershell
python tests/check_demo.py
```

مدیر پروژه برای بررسی مدل واقعی و باز نگه داشتن صفحهٔ دمو می‌تواند مسیر فایل تنظیمات خصوصی را به اسکریپت بدهد. اسکریپت تنظیمات مدل را مستقیماً از آن فایل می‌خواند.

```powershell
python tests/check_demo.py --env-file .env --keep-open
```

در مرورگر، صفحهٔ [میزبان دمو](http://127.0.0.1:8001/) را در نمای موبایل و دسکتاپ باز کنید. بررسی کنید دکمه و کادر پیام در دسترس باشند و پاسخ مدل برای «برای فروشگاه کیف و کفش از کجا شروع کنم؟» کوتاه، مشخص و مرتبط باشد. برای قطع و وصل شبکه، یک پیام بفرستید و پس از بازگشت اتصال «تلاش مجدد» را بزنید. همان پیام باید بدون رفرش و بدون حباب تکراری ارسال شود.

## اجرای دستی سرویس‌ها

وابستگی‌های پروژه را از `requirements.txt` نصب کنید. با `LAUNCHO_MOCK_URL` می‌توانید ویجت اصلی را بدون فایل `.env` و بدون کلید مدل اجرا کنید. در این حالت چت از پاسخ‌های محلی استفاده می‌کند. پس از اجرای هر دو سرویس، `http://127.0.0.1:8000/widget/widget.html` را باز کنید و فرم آزمایشی را تا مرور و تأیید ادامه دهید.

ترمینال اول، از ریشهٔ پروژه

```powershell
python -m uvicorn app.mock_launcho:app --host 127.0.0.1 --port 8001
```

ترمینال دوم، از همان ریشه

```powershell
$env:LAUNCHO_MOCK_URL = 'http://127.0.0.1:8001'
$env:LAUNCHO_API_URL = ' '
$env:LAUNCHO_API_KEY = ' '
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

صفحهٔ [میزبان محلی](http://127.0.0.1:8001/) لودر واقعی را از پورت ۸۰۰۰ بارگذاری می‌کند. دکمهٔ گفتگو را باز کنید و بپرسید «هزینه برام زیاده، چه گزینه‌ای دارم؟». در شروع گفتگو باید مسیر رسمی تعرفه دیده شود. پس از تکمیل گزینه‌های پیش‌نویس، با یک سؤال دربارهٔ پرداخت قسطی، پیشنهاد آزمایشی را بررسی کنید. برای تست لحن، یک سؤال دربارهٔ راه‌اندازی فروشگاه کیف و کفش بپرسید و کوتاهی پاسخ، ارتباط گزینه‌ها با محصول و حداکثر یک سؤال پیگیری را بررسی کنید.

فایل `content/launcho-mock.json` حاوی دادهٔ آزمایشی داخلی و جشنوارهٔ ساختگی است؛ قرارداد API واقعی نیست. اعداد نمونه با صفحات رسمی در ۲۰۲۶/۱۱/۱۱ تطبیق داده شده‌اند، ولی همچنان تعرفهٔ زنده نیستند و به مشتری نمایش داده نمی‌شوند. ویجت محلی با پروفایل `widget` گزینه‌های `test_only` را از `content/launcho-widget-catalog.json` می‌خواند. پروفایل `unavailable` فهرست خالی و پروفایل `test` دادهٔ آزمون قرارداد را برمی‌گرداند. اتصال gateway آزمایشی فقط loopback را می‌پذیرد؛ سرور mock را هم طبق دستور بالا فقط روی `127.0.0.1` اجرا کنید. مسیر ایجاد پیش‌نویس پایدار آزمایشی اضافه شده؛ پرداخت ندارد. برای گزینه‌های ساخت، پروفایل صریح test در راهنمای نسخهٔ ۲ توضیح داده شده است. اتصال واقعی از تنظیمات مستقل لانچو استفاده می‌کند.

پاسخ‌های موفق API علاوه بر `ok` و `data`، نشان `simulation: true` و هشدار `notice` دارند. اعداد `/pricing` فقط برای بررسی قرارداد در سمت سرور هستند؛ آن پاسخ را مستقیم در ویجت رندر نکنید. متن جشنواره باید «آزمایشی» و «برای خرید اعتبار ندارد» را نشان دهد و کاربر را به پرداخت برای دریافت این جشنواره دعوت نکند.

`GET /pricing` اطلاعات مشترک (دوره‌ها، دامنه‌ها و هزینهٔ راه‌اندازی) را با `serviceDetails.shop` و `serviceDetails.website` برمی‌گرداند. فیلدهای `setupIncludes`، `planIncludes` و `installment` دیگر در ریشهٔ پاسخ بدون نوع خدمت نیستند؛ آن‌ها زیر نوع مربوطه قرار دارند. مصرف‌کنندگان فعلی هسته فقط فیلدهای مشترک را برای اعتبارسنجی می‌خوانند و حالت محلی برآورد مبلغ نمی‌سازد. برای دریافت اطلاعات یک نوع، از `GET /pricing?kind=shop` یا `GET /pricing?kind=website` استفاده کنید؛ پاسخ شامل `kind` و جزئیات همان نوع در ریشه است. پارامتر نامعتبر رد می‌شود. فیلدهای مشترک در هر دو پاسخ یکسان باقی می‌مانند.

اقساط فقط به هزینهٔ راه‌اندازی تعلق دارند و برای سایت و فروشگاه جدا ثبت شده‌اند. `giftUsage` مصرف اعتبار ماهانه و منتقل‌نشدن مانده را مشخص می‌کند. در `POST /offers/match`، مقدار اختیاری `planMonths` فقط `3`، `6` یا `12` است؛ نبود آن مجاز است و دوره در صلاحیت پیشنهاد آزمایشی اثری ندارد. قواعد این پیشنهاد، شرایط کمپین واقعی لانچو نیستند. تخفیف رسمی دوره‌های بلندتر اشتراک با جشنوارهٔ آزمایشی و کد تخفیف فرق دارد.

برای بررسی خودکار مسیر API ساختگی تا پاسخ و تاریخچهٔ گفتگو، بدون تماس با مدل یا سرویس بیرونی:

```powershell
python -m unittest discover -s tests -p test_mock_launcho.py -v
```

ابهام‌های منابع و محدودیت‌های این بررسی در [گزارش بررسی محتوا و API](launcho-content-api-review.md) ثبت شده‌اند.

اطلاعات عمومی تأییدشده دربارهٔ قابلیت‌ها، نمونه قالب‌ها و روش راه‌اندازی، به همراه پیوند منبع در `content/launcho-public.json` قرار دارند. امکان جشنواره در پنل فروشنده با پیشنهاد خرید اشتراک لانچو فرق دارد.

## اتصال پیش‌نویس و پیگیری وضعیت

برای آزمایش با سرویس رسمی، آدرس پایه و توکن را در `LAUNCHO_API_URL` و `LAUNCHO_API_KEY` قرار دهید. پس از تأیید قرارداد و دسترسی محیط آزمون از طرف لانچو، `LAUNCHO_ENABLE_DRAFTS=1` را تنظیم کنید. مقدار پیش‌فرض این گزینه `0` است.

دستیار انتخاب‌های کاربر را با فهرست رسمی تطبیق می‌دهد. ساخت پیش‌نویس با دکمهٔ تأیید و کلید ثابت تکرار درخواست انجام می‌شود. لینک رسمی در تب تازه باز می‌شود تا کاربر بتواند از همان گفتگو وضعیت را بررسی کند. در مرحلهٔ مرور، اگر کاربر دربارهٔ هزینهٔ بالا یا پرداخت قسطی سؤال کند، درخواست پیشنهاد با دورهٔ انتخاب‌شده و نشانه‌های ثابت به لانچو ارسال می‌شود. واجد شرایط بودن در فرم رسمی تعیین می‌شود.

رخدادهای `session_started`، `draft_created` و `draft_status_checked` در سطح INFO ثبت می‌شوند. این رخدادها برای شمارش مرحله‌ها قابل استفاده‌اند و متن پیام یا شناسهٔ کاربر در آن‌ها ثبت نمی‌شود.
